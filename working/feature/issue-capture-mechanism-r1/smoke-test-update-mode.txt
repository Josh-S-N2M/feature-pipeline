STATIC VERIFICATION — AC-NFR-3-a (idempotency on empty diff)
===========================================================================

AC TEXT: When /capture-issue --update <path> is invoked and the diff between
current and proposed state is empty, the system shall report "no change" to
the user and shall not present an approval prompt or write the file.

Mapped to: AT-048 (update_mode_empty_diff_reports_no_change_with_no_prompt_no_write)

Evidence location:
  .claude/agents/issue-capture-author.md
  Section: "### Step 3 — Idempotency check (AC-NFR-3-a)"

Step 3 declares (excerpt from agent body):
  "If the proposed new status: equals the current status: AND no per-state
  companion fields are changing, this is a no-op:
  - Report (no change — status already <status>) to the user
  - DO NOT call Write
  - Exit cleanly"

  "This is the AC-NFR-3-a idempotency guarantee: running /capture-issue
  --update <path> twice with the same target state is safe. The second
  invocation detects the empty diff and exits without writing."

Workflow position: Step 3 fires BEFORE step 4 (OLD->NEW preview compute)
and step 5 (AskUserQuestion). On the empty-diff path:
  - Step 3 exits cleanly
  - Step 4 and step 5 are NOT reached
  - No AskUserQuestion fires
  - No Write fires

Coverage assessment: COVERED
  - Empty diff detected at step 3 (before AskUserQuestion and Write)
  - No approval prompt (step 5 not reached)
  - No write (step 6 not reached)
  - User receives "no change" report
  - File mtime is untouched (no Write call issued)
