# ADR-0009: Stage handoff carries a structured rationale brief; three-layer enforcement

## Status

Accepted — 2026-05-12 (template-migrated from v1.0.0 of the same date)

## Context

Blueprint v2 specified append-only artifacts with bidirectional supersession links (ADR-0005). The mechanism preserves decision history. But it does not address the practical problem at handoff time: a downstream sub-agent receiving an upstream artifact needs to know WHY decisions were made, not just WHAT was decided.

Research round 2 surfaced three converging findings:

1. External memory should be the source of truth for durable facts; the compaction summary is a navigation tool, not a memory store (claim C-R2-0017).
2. Structured compaction templates outperform freeform summarization; required sections act as checklists preventing silent information loss (claim C-R2-0016).
3. 79% of multi-agent failures originate from specification and coordination issues rather than model capability (claim C-R2-0025).

Cross-stage rationale loss is one of the named failure modes: downstream stages forget *why* a resolution was chosen and contradict it. This is MAST FM-2.6 (reasoning-action mismatch, 13.2%) and FM-2.5 (ignoring other agents' input, 1.9%) when it manifests through unstructured handoff.

## Decision

**Every sub-agent invocation in the feature-pipeline starts with a structured rationale brief.** The brief is generated by the orchestrator at stage-transition time and prepended to the sub-agent's invocation prompt as its first content section.

The brief follows a mandatory template (no freeform); the template includes Session Intent, Decisions Inherited, Decisions Added in Prior Stages, Active Constraints, Open Items From Upstream, Previously-Resolved Issues, and Files You Should Read (in order). Brief size targets 500-1500 tokens.

Three layers of enforcement compose: Layer 1 (orchestrator constructs and prepends the brief), Layer 2 (knowledge skills instruct sub-agents to honor the brief), Layer 3 (next critique stage verifies brief-honor).

## Decision Details

| Item | Content |
|---|---|
| Decision | Mandatory structured rationale brief at every stage handoff; three-layer enforcement (orchestrator constructs, skills instruct, critic verifies); 500-1500 token budget. |
| Why now | Without the brief, cross-stage context loss is the practical pathology — ADR-0005's structural impossibility-of-loss requires runtime surfacing to be effective. |
| Why this | Templated brief outperforms freeform (claim C-R2-0016); LLM-summarization at handoff lengthens trajectories 13-15% (claim C-R2-0014); three layers compose because each alone fails predictably (data without instruction, instruction without data, post-hoc detection without prevention). |
| Known unknowns | Whether 500-1500 token brief budget is right (may need to grow for very ADR-rich features); whether Layer-2 instruction text duplication across knowledge skills creates skill-bloat (currently shared via documentation-criteria per ADR-0011). |
| Kill criteria | If 3+ feature runs produce critique-detected MAST FM-2.6 (reasoning-action mismatch) issues that the brief contained sufficient information to prevent, the brief mechanism is not landing; revise the three-layer enforcement to be more aggressive (e.g., automated pre-invocation contradiction check). |

## Rationale

Three failure-mode findings make the brief load-bearing:

(1) Claim C-R2-0024 (MAST data) names FM-2.6 reasoning-action mismatch at 13.2% and FM-2.5 ignoring other agents' input at 1.9% — both directly addressable by surfacing prior decisions at the receiving agent's invocation.

(2) Claim C-R2-0027 documents 53-86% token duplication across handoffs — structured brief reduces this by referencing rather than embedding full upstream artifacts.

(3) Claim C-R2-0016 documents structured templates outperforming freeform — the brief is the explicit application of that finding to handoff context.

Three-layer enforcement is the right defense-in-depth: each layer alone has a predictable failure mode (Layer 1 alone = data without instruction; Layer 2 alone = instruction without data; Layer 3 alone = post-hoc detection costing iterations). All three together provide structural defense.

## Options Considered

**Option 1: No brief; rely on artifact references alone (v2 status quo).**
- Pros: simplest; no orchestrator-side state.
- Cons: leaves pipeline exposed to 13.2% reasoning-action mismatch and adjacent failures.

**Option 2: Single-layer enforcement (orchestrator-only).** Brief present, no instruction to consult.
- Pros: simpler than three-layer.
- Cons: predictable failure (sub-agent ignores).

**Option 3: Full artifact embedding.** Include every upstream artifact in full in the sub-agent's invocation.
- Pros: solves rationale availability.
- Cons: blows the context budget; per claim C-R2-0027 source of the 53-86% token duplication.

**Option 4: Brief generated by an LLM at handoff time.**
- Pros: rich natural-language summarization.
- Cons: LLM summarization paradoxically lengthens trajectories by 13-15% (claim C-R2-0014); templated extraction is more reliable.

**Option 5: Brief as a side artifact rather than prompt prepend.**
- Pros: keeps the prompt clean.
- Cons: file-path references can be ignored by an agent that doesn't read them; loses Layer-1 guarantee.

**Option 6 (Selected): Mandatory structured brief at prompt prepend + three-layer enforcement.**
- Pros: structural defense against named failure modes; templated extraction is deterministic; three layers compose; brief size budget bounds cost.
- Cons: orchestrator complexity grows; Layer-2 instruction text duplicated (mitigated via shared skill); Layer-3 adds critique work.

## Consequences

### Positive Consequences

- **Defense against MAST FM-2.6 (reasoning-action mismatch, 13.2%)** by making rationale prominent at every invocation.
- **Defense against MAST FM-2.5 (ignoring other agents' input, 1.9%)** by explicit instruction to honor upstream decisions.
- **Defense against MAST FM-1.3 (step repetition, 15.7%) and FM-2.1 (unexpected conversation reset, 2.2%)** by surfacing previously-resolved issues in the brief.
- **Reduces context bloat from full-artifact handoffs.** Per claim C-R2-0027, multi-agent token duplication ranges 53-86%; structured brief reduces this.
- **Bridges the per-feature ledger (ADR-0008) into runtime context.** The ledger is the persistent store; the brief is the per-invocation surfacing.
- **Mandatory template prevents silent information loss.** Per claim C-R2-0016, structured templates outperform freeform.

### Negative Consequences

- Orchestrator complexity grows. The brief generator must read multiple sources, deduplicate, summarize, and format. Mitigated by isolating brief-generation into a clear sub-routine.
- Layer-2 instruction text duplicated across knowledge skills. Mitigated by placing it in `documentation-criteria` (per ADR-0011, the canonical document skill loaded by every sub-agent that authors documents).
- Layer-3 verification adds critique work. Each critique stage's checklist grows by three checks. Acceptable ~5-10% per-critique latency.
- Brief generation is potentially flaky if the ADR or ledger files are mis-formatted. Mitigated by Layer 1's pre-invocation validation.

### Neutral Consequences

- The brief is JSON-serializable-equivalent (markdown with well-defined sections). Could be promoted to JSON format if downstream tooling needs it. v1 stays markdown for human-readability during debugging.

## Architecture Impact

**Components that change:**
- Orchestrator skill (per ADR-0001): brief generation logic added.
- All knowledge skills (per ADR-0011, anchored in documentation-criteria): "Honoring the Rationale Brief" section added.
- All critique sub-agents (post-rename: synth-architecture-auditor and synth-cross-artifact-auditor per ADR-0017): Layer-3 verification checks added to their checklist.

**New dependencies introduced:**
- Every sub-agent invocation depends on the orchestrator constructing a valid brief.
- Brief generation depends on ADRs and issues-ledger being readable in well-known formats.

**Architectural constraints added:**
- Orchestrator MUST construct and prepend a templated brief to every sub-agent invocation.
- Brief MUST follow the mandatory template; freeform briefs forbidden.
- Brief size MUST fit within 500-1500 token budget.
- Knowledge skills MUST include the "Honoring the Rationale Brief" instruction (in body or via documentation-criteria reference).
- Critique sub-agents MUST include brief-honor verification in their checklist.

**Architectural constraints removed:**
- Implicit handoff via file paths alone is forbidden; brief is mandatory.

## Implementation Guidance

### Brief structure (mandatory template)

```markdown
## Rationale Brief — Stage <N>: <stage-name>

### Session Intent
<1-3 sentences: user intent, slugged feature, run-id>

### Decisions Inherited (immutable for this stage)
- ADR-<id>: <one-line summary> [version <semver>]

### Decisions Added in Prior Stages (this run)
- Stage <N> introduced ADR-<id>: <one-line summary>

### Active Constraints
- <constraint>: <one-line>

### Open Items From Upstream
- Item: <description>. Expected handling: <action>

### Previously-Resolved Issues (verified or dismissed; do not re-surface)
- Issue I-<id>: <summary>. Resolution: <brief>. State: verified at iteration <N>.

### Files You Should Read (in order)
1. <path> — <reason>
```

### Brief generation source-of-truth

- Inherited ADRs: read from `working/feature/<slug>/adrs/` filtering on `status: Accepted`.
- Active constraints: from manifest hard constraints + carried-forward soft constraints in current run's traceability.json.
- Open items: from upstream stage's output JSON.
- Previously-resolved issues: from `issues-ledger.json` filtering on `current_state in {verified, closed, dismissed}`, capped at 10 most recent.
- Files to read: orchestrator-selected based on stage.

### Layer-3 verification checks (added to every critic's checklist)

1. **Decision contradiction check.** Does the artifact contradict any decision in the upstream agent's rationale brief? If contradicting without corresponding `proposed_supersession`, that is HIGH severity (category: `adr_contradiction`).
2. **Open-item handling check.** Did the upstream agent address every Open Item? Each must be resolved or marked `deferred_to_<future-stage>`. Silent dropping is MODERATE severity (category: `dropped_open_item`).
3. **Re-surfaced verified issue check.** Did the upstream agent re-open any issue from `Previously-Resolved Issues` without `reopen_recommended` evidence? MODERATE severity (category: `step_repetition`).
