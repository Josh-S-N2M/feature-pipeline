## Purpose

This document exists to close three explicit prior surfaces:

1. **Q-3 from `codebase-analysis-report.md` line 200:** *"Agent inventory scope for UI-1 — are the 36 agent files all in-scope, or are some (esp. the six `synth-*` files) deprecated and excluded from MCP wiring consideration? **Blocks design-cc-completion.**"* Q-3 was flagged before per-layer Design but never received a structured 36-row response — the cc-design.md table is the inverse view (server → agents), not the demand view (agent → servers).
2. **ADR-0040 line 74 hedge:** *"Whether `design-iac` and `design-api` also occasionally touch audit-script Python (no current evidence; if true, they would be added in a follow-up — easy additive change)."* This matrix systematically tests that hedge and similar ones against every agent file rather than against the two candidates the ADR named.
3. **User Gate-4 Blueprint v2 review feedback:** the existing consumer-mapping approach is supply-driven (per-MCP-server → which agents); a demand-driven (per-agent → which MCP servers) view is needed to make silent omissions visible. The user dispatched this as "Track A2" before Gate 4 (Blueprint Approval).

This matrix is **additive only** — it does not modify cc-design.md or ADR-0040. If the matrix surfaces newly-proposed wiring, Blueprint v3 is triggered as a discrete revision; otherwise the matrix becomes a closure artifact stapled to the feature.

- **Audit-skill-invoker (intentionally narrow `auditing-cc-configs` family-skill consumer):** 1 agent — cc-critique. The skill family does the MCP-relevant work; the agent itself does not call MCP tools.

**Previously-untouched agents that genuinely need MCP wiring:** **NONE.** The 8 IN_CC_DESIGN agents are the complete demand-side set. **Blueprint v3 is therefore NOT triggered** by this matrix; the matrix is a closure artifact for Gate 4.

**Three biggest surprises from the sweep** (documented in Followup):

1. The synth-* set is **still wired into the orchestrator** (per the recent execution-pipeline-design-r1 commit cf48e5e — execute-orchestrator references "synthesis pipeline" in `synth-extractor.md` line 12). Q-3 wondered if these were deprecated; they are NOT — they remain active and their MCP-need verdict is "no evidence found" rather than "deprecated."
2. **`execute-task-code-producer` lists `KB-cc-design` in its `skills:` array but has no MCP wiring** — implementation-phase code-producer agents read design KBs but operate against the feature codebase, not MCP servers. This is intentional but worth recording for future features that might want Context7 (library docs) available at code-production time.
3. **`design-composer` has 19 KB skills loaded but zero MCP tools.** Composer is the cross-layer arbitrator and reads per-layer designs; it does not directly call any MCP server. This is by design (Composer reads structured per-layer outputs) but counter-intuitive given Composer's apparent reach. It is recorded here so a future feature can challenge it explicitly.

**New Q-CC-N items raised:** **NONE.** This matrix does not surface any architectural question that cc-design.md or ADR-0040 has not already surfaced. The matrix is closure-only.
